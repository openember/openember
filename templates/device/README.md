# __PRODUCT_NAME__

OpenEmber product project generated by `ember new`.

## Layout

```text
apps/product_app/     Product App
modules/              Pending-upstream modules
products/__MODEL__/   Model config (defconfig + hardware + launch)
product.default       Checked-in default model
kconfig/              Product options inserted into the functional menus
openember/            Framework sources (symlink or submodule)
build/<model>/        Per-model build tree (gitignore)
```

See OpenEmber `docs/design/product-scaffold-and-variants.md`.

## Build & run

```bash
./openember/scripts/ember menuconfig --product __MODEL__
./scripts/build.sh
./openember/scripts/ember run
```

After installing this checkout's CLI (`./openember/scripts/ember install`), use
`ember` directly. This updates the user command symlink and Bash completion;
an older standalone `openember-cli` may not support this workflow.

Add models under `products/<model>/`, then select one with
`ember menuconfig --product <model>`. Subsequent `build` and `run` reuse its
`build/<model>/.config`; `PRODUCT=<model> ./scripts/build.sh` also works.
`ember run --dry-run` displays the command without starting processes.
Build after editing configuration, and update `launch.yaml` if disabling a node.
`ember defconfig` explicitly resets defaults, backing up `.config.pre-defconfig`.
