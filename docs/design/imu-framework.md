# IMU 专用子框架

IMU 子框架属于 Sensor 组件，源码位于 `components/sensor/imu/`，暂不拆成独立组件或仓库。Sensor 公共层统一生命周期、身份、健康和诊断；IMU 子框架统一惯性数据语义、能力、配置、校准和驱动装配；各型号驱动拥有协议、应答匹配和设备差异。

## 分层及兼容

| 层级 | 接口与职责 |
| --- | --- |
| Sensor 公共层 | `ISensor`、SensorInfo、设备状态、`ISensorDiagnostics` 命名计数器 |
| IMU 专用层 | `IImu / ImuSample`、`IImuConfiguration`、`IImuCalibration`、`ImuDriverRegistry`、YAML 实例选择 |
| 型号驱动 | Yesense 等型号的数据协议、命令事务、能力限制及连接设置 |
| 工具与服务 | CLI 交互与记录；HI 对消息的适配；后续 Link 服务与 Web 展示 |

新头文件路径为 `openember/sensor/imu/imu.hpp`、`configuration.hpp`、`calibration.hpp`、`driver_registry.hpp`、`configuration_yaml.hpp`。命名空间仍为 `openember::sensor`；旧的 `openember/sensor/imu.hpp`、`imu_driver.hpp`、`imu_driver_yaml.hpp` 通过转发头保持兼容。原 `openember::sensor_drivers`、`openember::sensor_config` 和 `openember::yesense_imu` 目标名称保留。

配置和校准是可选接口，基础 `IImu` 不强制实现。使用方先查询能力；没有能力的驱动返回不支持，不能伪造成功或假定所有 IMU 都能修改频率、输出内容和波特率。

## 样本语义

加速度、角速度、磁场、温度分别携带有效性，单位为 m/s²、rad/s、tesla 和 ℃。输出内容变化后，驱动只交付当前帧实际测得的字段，不跨帧填充旧值。`orientation_present` 表示原始四元数是否存在；`orientation_valid` 额外要求已确认参考系与安装关系。两者不能互相替代。HI 利用 protobuf 方向子消息的 presence 保留此差别，接收端不能把缺少姿态当作单位四元数。

设备采样时间和主机接收时间分开；未知设备单调采样时间保持 0。配置期间驱动持续处理采样流，但可以合并多帧只交付最新样本，因此配置期间不保证全部线路帧被 CLI 记录。显示刷新率、驱动交付率、消息发布频率和硬件输出频率分别表达。

## 能力与配置

`ImuCapabilities` 描述配置访问是否启用、支持的频率/波特率、输出字段、RAM/Flash 和静态陀螺校准能力。频率使用 double，以支持其他型号的分数 Hz 输出率。字段以语义集合表达：加速度、角速度、四元数、温度、磁场、欧拉角和设备时间；厂商位掩码只出现在驱动内。输出欧拉角或设备时间不意味着公共样本已完成相应坐标系或时钟映射。

`ReadConfiguration()` 返回设备实际回读值及查询时间。无法确定的字段保持未知，不从 YAML、缓存、主机波特率或上一条设置命令推断。主机波特率单独返回。当前 RAM 值不能证明 Flash 内容，读取配置不会宣称配置已持久化。

`ApplyConfiguration()` 接收字段补丁和持久化方式，默认 RAM；Flash 必须显式选择。每个已尝试字段返回 APPLIED、REJECTED 或 UNCONFIRMED，允许表达前一项成功而后一项失败。未确认结果不能当作失败后自动重试写入，也不执行隐式回滚。Yesense 先读取当前配置，校验目标带宽，并按增大波特率、降低输出率、改变内容、提高输出率、降低波特率的顺序控制中间负载。

YAML 表示工程期望配置，RAM 表示临时设备配置，Flash 表示设备持久化请求。CLI 设置不会自动覆盖 YAML；设备波特率修改成功后，应由操作者明确更新后续启动所用的连接配置。

## Yesense 事务和访问边界

默认 Yesense、HI `yesense_readonly` 以及 `device.yaml mode: readonly` 均不发送设备查询、配置或校准命令。CLI 台架控制通过显式的直接连接和 `--device-control` 启用；只读 YAML 不允许被该选项隐式覆盖。此开关仅用于独立台架，不代表整机运动期间可以修改关键传感器。

设备控制与采样共用一个 SerialPort 和解析器，事务串行执行，按数据类及操作符匹配应答。正常查询不清空接收缓冲区。协议没有请求序号，超时后将配置会话置为未确认，要求显式关闭、重开；不自动重发有副作用的命令。串口关闭重开也不构成跨重启响应防重放协议，结果仍需结合回读判断。

设置输出率和输出内容需要 ACK 及实际回读一致。UART 波特率设置没有 ACK，驱动等待发送完成后在同一独占 fd 上切换主机波特率，清除旧速度接收数据，再查询实际设备波特率；验证失败会停止采集，结果为 UNCONFIRMED。操作者可关闭连接，设置 `host-baud`，再显式重连。驱动不会通过猜测多个串口速度自动恢复。

YIS321 使用文档明确的 1–400 Hz 配置表。高频编码在不同固件/型号中有歧义，不从其他型号推断。目标输出估算占用不得超过 UART 波特率的 80%，仍不代表经过实时性验收。串口原始设置通过 Linux termios2 保存/恢复，包含自定义波特率；Stop 仅恢复主机参数，不撤销已写入设备的 RAM/Flash 配置。

## 校准

`IImuCalibration::CalibrateStaticGyro` 独立于配置接口。结果区分请求已接受、已完成、已拒绝和未确认。Mock 返回模拟完成；Yesense ACK 仅报告 ACCEPTED，不据此宣称零偏质量或整个标定流程完成。

Yesense 要求连接至少 10 秒，最近至少 1 秒持续收到有进展的加速度/角速度，接收年龄不超过 100 ms，并通过静止启发式检查（角速度模长小于 0.05 rad/s、加速度模长在 9.3–10.3 m/s²）。这不是可靠的设备上电检测或标定质量证明。发送后操作者仍须保持静止至少 1 秒。设备 ACK 异常或超时报告未确认，不自动重复校准。静态陀螺零偏校准与安装方向、姿态参考系标定是不同工作，不会自动设置 `orientation_valid=true`。

## 整机集成及当前范围

当前实现 IMU 子框架、Mock/Yesense 可选能力及台架 CLI。HI 保持只读采集；本轮不增加远程配置服务或 Web 配置按钮。

后续链路为 Web Console / CLI Link 客户端 → 公共配置服务 → 唯一 HI owner → 驱动。整机状态管理和服务端共同决定是否允许修改关键 IMU；运行中被运控依赖时不能由网页直接重开串口。前端选项从能力接口生成，设备实际配置、工程期望值、正在应用状态和结果分开展示。还需定义公共消息、权限、请求去重、配置代次和依赖方恢复流程，再开放 Web 控制入口。

## 2026-11-21 验证记录

开发机与 RK3588 已通过 Mock、PTY 配置事务及 CLI 回归，覆盖 RAM/Flash 编码、读回不一致、拒绝、超时、波特率无 ACK、带宽检查、部分字段、校准前置条件与接受状态。板上另外验证旧接口生命周期、原只读配置、加速度/角速度部分输出及 HI/Link 发布链路。自定义 76800 BOTHER 的原始 termios2 在打开/关闭后逐字节恢复。

开发机真实 USB YIS321 只读采集约 400 Hz；strace 确认默认只读采集不向设备写命令。另一次显式控制会话仅发送了查询类 0x02/0x03/0x04，没有发送参数设置，读回为 400 Hz、加速度/角速度/四元数/欧拉角/时间戳、设备 UART 460800；主机 CDC 打开速度为 921600。两者不同不影响该 USB 链路，不能因此替代设备 UART 实际配置。

真实设备首次打开后立即发查询曾无应答；在首批采样到达或最多 200 ms 的初始等待之后，三项配置查询正常返回，已加入启动阶段丢弃过早命令的伪设备回归。该等待也允许输出关闭时继续查询。真实设备尚未执行输出参数写入、波特率修改、Flash 写入或校准；这些写操作当前只通过伪设备验证，不代表型号/固件的实机写入验收。
