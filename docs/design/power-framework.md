# 通用电源设备与控制校验

`components/power` 提供 `openember::power` C++17 接口及可选公共消息适配。核心不包含具体 PMU 协议、电池数量、机型资源映射或低电量处置策略。构建选项为 `OPENEMBER_COMPONENT_POWER`，默认关闭，依赖 hardware；启用公共 C++ 消息时同时提供 `openember::power_protocol`。

## 设备与资源

`IPowerDevice` 包含 Start、Stop、GetCapabilities、Read、Execute 和带发送前校验的 ExecuteChecked。资源分为电源通道、风扇和灯，电池通过单独的 ID 列表描述；只读设备将资源的 writable 标记为 false。通道只接受 0/1；风扇和灯使用归一化的 [0,1]，仅具开关能力时也只接受 0/1。不在该接口加入电池切换、整机休眠、故障清除或固件升级的字符串逃生通道。

`Snapshot` 中测量和连接状态使用 optional 区分未知与有效零值。各资源保留独立序号、设备采样时间、主机接收时间、时钟域和接收新鲜度；未知采样时间保持零。重复读取快照不能刷新观测序号或时间，PMU 收到应答也不能证明下游 BMS 测量新鲜。消费端需要独立的到达超时及有效性判断。

驱动只有在独立观测确认执行结果时才能返回 Confirmed，ACK 或回显最多是 Accepted。异常发生在设备写入之后时返回 Unknown，不能声称操作没有执行。所有驱动必须在实际发送前检查 deadline；控制层还会在进入执行前检查一次。Mock 的确认结果来自模拟状态模型，不代表真实硬件验收。

## 请求校验与去重

`Controller` 由单个控制执行器串行调用，Execute 可能阻塞；不能直接放在 Link 或 Web 回调执行，也不是实时运控周期接口。上层负责有界排队和调度，实际执行时提供当前单调时间，不使用排队时保存的旧时间。

请求绑定设备 ID、服务会话及服务单调时钟域。适配层必须从认证结果产生 principal，`Context::authorize` 从当前资源操作权限和整机就绪许可动态判断授权；不再使用静态 `system_ready` 布尔值或资源白名单。不能从请求 Header、用户声明或未知状态直接授予权限。能力中的 `enable_requires_ready` 和 `disable_requires_ready` 分别声明开启及正常关闭的协调要求；无需协调的资源不要求许可。

请求标识、设备标识、资源、principal、会话和时钟域使用 1–127 字节 ASCII 标识，允许字母、数字以及 `_-.:/@`。拒绝 NUL 和控制字符，避免 C/C++ 字符串截断产生不同身份解释。资源上限 64、电池上限 16，构造时拒绝重复或非法能力。

执行前在历史表中预留记录，按 principal 和 request_id 去重。同一请求重发返回第一次结果；更换目标、设备、期限或会话内容属于冲突。执行抛异常时保留 Unknown，重复请求不再执行。权限检查先于缓存读取，因此撤销权限不会被缓存绕过。已过期的请求始终拒绝。

P0 使用固定会话历史，不淘汰已执行的请求，即使原期限已过也不允许用同一 ID 换期限重放。默认容量 256，可配置 1–4096；容量满时拒绝新控制并返回 Busy，旧的未过期重复请求仍可查询结果。后续常驻服务必须处理并展示容量，协调更换为新的服务会话；不能静默清表、复用旧会话或宣称无限期运行。尚未实现持久化历史、多进程仲裁和自动会话切换。

Controller 不执行网络身份认证、产品就绪计算、控制租期、自动恢复、重试或自动上电。重建 owner 必须生成新服务会话，旧请求因此失效；不能从历史目标恢复供电。多个控制源间的优先级和产品上下电流程在后续产品服务定义。

## 动态权限与就绪许可

`Authority` 是本进程内的授权状态，不是网络认证协议。`SetPermissions` 按 principal、资源和操作（SetLevel / Enable / Disable）配置精确授权，空配置即拒绝，不支持隐式通配。`ForAuthenticated` 只能由已经完成身份认证的服务适配器调用；从消息 Header 中复制用户名再调用该方法不构成认证。Context 捕获共享的授权状态，撤销权限后，已产生的 Context 也会立即看到新策略；Authority 关闭或销毁后遗留 Context 拒绝操作；Close 是本会话不可逆的关闭，新的就绪更新不能使其恢复。

`BindTrustedIssuer` 由可信管理者适配器绑定会话，新管理者会话立即撤销旧许可；重复绑定同一会话不能重置重放序号。`ApplyTrustedPermit` 只接收可信进程代码已经验证来源的数据，不得直接暴露为接收普通 Topic 或用户请求的服务。许可绑定机器人、设备、PMU 服务会话、时钟域、管理者会话和资源操作，要求单调递增序号，有效期最多 1 秒，并隔离真实与仿真环境。域外单调时钟不得直接拿来比较，跨设备许可需要适配器处理可信期限换算。空许可可以撤销资源的就绪资格，`RevokeReadiness` 也不会重置序号防线。

Controller 在入队前检查操作权限和就绪，实际后端经 `ExecuteChecked` 在写入前再次检查当前权限、许可和期限。包含内部队列的设备必须重写 ExecuteChecked，将 ExecutionCheck 一直携带到实际发送处；不能在进入设备队列时检查一次就算完成。校验函数必须是本地、线程安全、非阻塞的函数，不在串口线程上发起 RPC。发送前拒绝保留 Unauthorized、NotReady、Expired 等原因；发送后无法确定结果则保留 Unknown。

重复请求仅查询已保存结果时仍检查当前操作权限，但不重新要求就绪许可，因为不会重新写设备。新请求必须重新满足许可。许可失效或管理者重启不会自动发出关电、恢复目标或清故障命令，保护动作必须走独立策略。

## 公共消息适配

`openember::power_protocol` 将 `PowerControlRequest` 的 oneof 转成领域目标并交给 Controller，生成 `PowerControlResult`。没有 target 的消息会被拒绝；显式 `channel_enabled: false` 是有效关电目标，不能与缺失混淆。未知操作不降级成关电。Describe 生成资源能力和历史容量描述。

适配器不启动 Link 服务，不注册 Topic，也不填发布 Header；实际 owner 负责消息头、认证、最大报文长度、队列和工作线程。错误响应中的设备与会话标识来自服务自身，不相信请求中伪造的目标身份。领域库本身不依赖 Protobuf，启用消息时增加独立链接目标，避免设备驱动必须依赖消息运行时。

## 当前验证与后续

P0 的 Mock 用例覆盖权限、会话与时钟域、期限、非法目标、只读能力、上电就绪条件、重复与冲突、结果未知、写入后异常、历史容量及重启不恢复旧目标。协议测试通过公共消息序列化后调用 Mock 控制器；旧电源消息兼容性和 Nanopb oneof 编解码另外验证。

产品已接入 LPIO、设备 YAML、告警和只读 HI；另提供受控 PMU 运行层及整机就绪评估接口，默认启动入口仍只读。公共协议版本标记为 2，追加关闭协调能力字段，旧遥测字段不变。新增 Authority 用例覆盖操作级权限、动态撤销、许可身份/时钟/环境/期限/序号、管理者切换、缓存语义，以及发送前权限与就绪撤销。产品另已提供使用公共协议适配器的认证 Link 服务、CLI/Web 入口及有界执行队列。真实整机就绪发布者仍待接入，不能用现有仿真整机状态放行真实 PMU 上电。
